# Резервные копии базы CatManDog

Сервер раз в шесть часов проверяет, прошло ли семь дней с последней копии. Если копий ещё нет, первая создаётся после запуска. Используется `pg_dump` в формате custom. Перед загрузкой архив проверяется через `pg_restore --list`, после загрузки скачивается из R2 и сравнивается по SHA-256. Только после этого удаляются копии старше двух последних.

Копии содержат учётные записи и заказы. Нужен **отдельный закрытый** R2 bucket в классе Standard. Не включайте публичный домен или `r2.dev` для этого bucket. Токен R2 должен иметь `Object Read & Write` только для backup bucket. Токен для публичных фотографий здесь не используется.

В Railway у сервиса CatManDog задаются `BACKUP_ENABLED=true`, `R2_ACCOUNT_ID`, `R2_BACKUP_BUCKET`, `R2_BACKUP_ACCESS_KEY_ID` и `R2_BACKUP_SECRET_ACCESS_KEY`. `DATABASE_URL` уже подключён к Postgres. Ключи не добавляются в репозиторий. После деплоя сервер попробует создать первую копию через 30 секунд; в логах должна появиться строка `Database backup verified`. Статус двух последних копий доступен владельцу через `GET /api/admin/backups`.

При ошибке новая копия не считается успешной, а оставшиеся копии не удаляются. Сервер повторит попытку через шесть часов. Проверяйте дату последней копии в админском API хотя бы раз в неделю: этот механизм не отправляет отдельное уведомление об ошибке.

Для восстановления скачайте нужный `.dump` в доверенной среде с временными R2 credentials и сначала проверьте `pg_restore --list database.dump`. Восстанавливайте в **новую пустую** базу и проверяйте данные, прежде чем переключать сайт. Команда: `pg_restore --no-owner --no-acl --dbname "$NEW_DATABASE_URL" database.dump`. Не запускайте восстановление поверх рабочей базы без отдельного плана переключения.
