# Серверная часть CatManDog

## Подготовлено

- Один Node.js сервис обслуживает существующий сайт и API на том же домене
- PostgreSQL подключается через `DATABASE_URL`; при запуске создаются таблицы и импортируются карточки и варианты из каталога
- Исходные розничные цены сохраняются отдельно от цены продажи и закупочной цены
- Все импортированные цены требуют подтверждения оператором до настоящего заказа
- API рассчитывает состав корзины и доставку сам, не доверяя цене из браузера
- Заказы, позиции, история статусов, обращения, клиенты и питомцы имеют отдельные таблицы
- У оператора есть страница `/admin` для заказов, цен, закупки, остатков и доступности
- Регистрация, подтверждение email, вход, выход и восстановление пароля подготовлены с одноразовыми ссылками, хешированием пароля и серверной сессией в HttpOnly cookie
- Настоящий кабинет загружает питомцев, контакты, планы, выбранные клиники и поездки с сервера. Изменения сохраняются в PostgreSQL; версия записи защищает от незаметной перезаписи с другого устройства
- Настоящий кабинет не принимает из браузера заказы, промокоды и бонусы; локальный пример Лео остаётся отдельным демонстрационным режимом
- Формы поддержки и возврата готовы к отправке в API после проверки черновика. Сервер сохраняет обращения в PostgreSQL, оператор видит их в `/admin`; демонстрационные номера отклоняются. Фото пока не загружается
- Фото хранятся в R2 bucket `catmandog-media` и открываются через `img.catmandog.es`; рабочая версия сайта обращается к ним напрямую

## Включение

`DATABASE_URL` уже должен быть reference variable от Railway Postgres. Остальные параметры перечислены в `.env.example`. Секреты не добавлять в Git.

Публичный сайт и API запускаются командой `npm start`. `GET /api/health` проверяет соединение с PostgreSQL. `GET /api/config` возвращает включенные функции. Локально без базы сайт продолжает обслуживаться, API сообщает о недоступной базе.

Три флага по умолчанию выключены: `ACCOUNTS_ENABLED`, `ORDERS_ENABLED`, `SUPPORT_ENABLED`. Приём заказа также требует `PAYMENTS_ENABLED`. Для настоящих аккаунтов нужны `RESEND_API_KEY`, `RESEND_FROM` и публичный HTTPS-адрес `PUBLIC_BASE_URL`. Домен отправителя подтверждён, Resend принял тестовое письмо, а `ACCOUNTS_ENABLED=true` активен в Railway. API на `https://catmandog.es/api/config` возвращает `accountsEnabled=true` и `emailEnabled=true`; на основном сайте доступны формы входа и регистрации. Формы обращений можно включить отдельно через `SUPPORT_ENABLED=true`, когда команда готова отвечать на сохранённые запросы. Оплата и оформление пока остаются демонстрационными.

## Что ещё требуется для реального запуска

1. Проверить регистрацию, подтверждение email, вход и сброс пароля на настоящем сайте с доступным тестовым почтовым ящиком. Письма о заказе и обращении ещё не реализованы
2. Подключить Stripe после подготовки компании; сервер должен подтверждать платёж по webhook до статуса «оплачен»
3. Проверить границу зоны доставки и адреса в городе Валенсия; сейчас почтовый индекс проверяется грубо, адрес помечается как непроверенный, интервал - как незабронированный
4. После запуска реальных заказов связать их историю с кабинетом. В текущей таблице заказов нет привязки к питомцу. Если понадобится перенос локального прототипа, запрашивать его отдельно после подтверждения владения аккаунтом
5. Проверить на тестовом обращении ответ оператора по email и затем включить `SUPPORT_ENABLED`. Загрузка фото требует R2
6. Принять решение по подарочным наборам с динамическим составом: сервер пока не считает их как обычные SKU
7. Настроить резервное копирование, аудит и наблюдение за ошибками перед приёмом реальных заказов

## R2

В `assets/` было 1150 файлов общим размером около 874 МиБ. 19 октября 2026 года они загружены в bucket `catmandog-media` в Western Europe. Повторная проверка `npm run assets:r2 -- --verify` нашла 1150 совпадений по размеру и SHA-256, без пропусков. Токен миграции ограничен этим bucket и действует одну неделю; временные локальные файлы с ключами удалены.

20 октября к bucket подключён публичный домен `img.catmandog.es`. По HTTPS проверены все 1150 объектов: 1146 совпали по статусу и размеру, 4 SVG - по SHA-256 содержимого, поскольку Cloudflare не возвращает для них `Content-Length` в ответе HEAD. На Railway включены `R2_PUBLIC_BASE_URL` и `R2_MEDIA_REDIRECT_ENABLED`; свежий запрос `/assets/hero-happy.png` ответил `302` на R2. Ссылки в интерфейсе указывают на R2 напрямую, файлы исключены из актуальной версии Git и будущих сборок Railway. Старые копии остаются в истории Git и могут быть восстановлены. Новые изображения нужно сначала загрузить в R2 по тому же ключу `assets/...`, проверить публичный URL, затем добавить ссылку в каталог. Скрипт `npm run assets:r2 -- --apply` позволяет загрузить временно подготовленные локальные файлы при наличии ограниченного токена; `--verify` сверяет размер и SHA-256.

19 октября `catmandog.es` добавлен в бесплатную зону Cloudflare. В неё перенесены DMARC и `_domainconnect`; парковочные A-записи GoDaddy заменены на CNAME Railway, добавлена TXT-запись для проверки домена. В Railway создан собственный домен `catmandog.es` на порту 8080. В Cloudflare опубликованы правила перенаправления `www` на основной домен для HTTP и HTTPS с сохранением пути и параметров. У GoDaddy установлены NS `dion.ns.cloudflare.com` и `lauryn.ns.cloudflare.com`; регистратор подтвердил запрос, но обновление делегации и проверка Railway ещё ожидаются.

Позже 19 октября делегирование Cloudflare стало активным. CNAME основного домена переключён с DNS only на Proxied согласно инструкции Railway; режим SSL/TLS Cloudflare - Full. Авторитетные DNS Cloudflare и публичные резолверы возвращают IP Cloudflare. Проверка HTTPS через актуальные IP: главная страница и `/api/health` отвечают 200, сертификат `catmandog.es` действителен, HTTP и `www` перенаправляются на `https://catmandog.es/`. DNS-серверы компьютера тоже обновились, но системный `getaddrinfo` и Safari в момент проверки ещё использовали закешированные парковочные IP GoDaddy. Железный признак старой парковки - её ответ `window.location.href="/lander"`. Railway UI всё ещё показывал `Waiting for DNS update`. Повторить обычную проверку после очистки системного кеша или его истечения, не обходя предупреждение браузера.

В Resend создан и подтверждён отдельный отправляющий домен `notify.catmandog.es` (регион Ireland). Его DKIM TXT и две CNAME-записи для отправки добавлены в Cloudflare как DNS only; приём писем в Resend выключен. Случайно созданный неиспользованный ключ `CatManDog transactional` с правом Sending access для всех доменов удалён 19 октября; существующий ключ Estate CRM не изменён. Пользователь создал новый ключ `CatManDog transactional - notify.catmandog.es`; в Resend проверены право Sending access и ограничение на `notify.catmandog.es`. В Railway применены `PUBLIC_BASE_URL=https://catmandog.es/`, `RESEND_FROM=CatManDog <no-reply@notify.catmandog.es>` и `RESEND_API_KEY`; ключ не хранится в Git. Ошибочная пустая переменная с именем `https://catmandog.es/`, из-за которой сборка сообщала `secret https not found`, удалена. Последующий выпуск прошёл успешно, `/api/config` показал `emailEnabled=true`. Из Railway Console отправлено письмо на тестовый адрес Resend `delivered@resend.dev`; API Resend принял его (`RESEND_TEST_ACCEPTED`). После добавления `ACCOUNTS_ENABLED=true` новый выпуск стал активным: `/api/config` на домене Railway и в Safari на `catmandog.es` показал оба флага `true`. Страницы входа и регистрации открываются на основном домене. Доставку письма в настоящий ящик, подтверждение email и восстановление пароля ещё нужно проверить сквозным тестом.
