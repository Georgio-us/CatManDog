# Серверная часть CatManDog

## Подготовлено

- Один Node.js сервис обслуживает существующий сайт и API на том же домене
- PostgreSQL подключается через `DATABASE_URL`; при запуске создаются таблицы и импортируются карточки и варианты из каталога
- Исходные розничные цены сохраняются отдельно от цены продажи и закупочной цены
- Все импортированные цены требуют подтверждения оператором до настоящего заказа
- API рассчитывает состав корзины и доставку сам, не доверяя цене из браузера
- Заказы, позиции, история статусов, обращения, клиенты и питомцы имеют отдельные таблицы
- У оператора есть страница `/admin` для заказов, цен, закупки, остатков и доступности
- Регистрация и вход подготовлены с хешированием пароля и серверной сессией в HttpOnly cookie
- Фото можно перенести в R2 скриптом `npm run assets:r2 -- --apply`; до переноса сайт использует прежние локальные файлы

## Включение

`DATABASE_URL` уже должен быть reference variable от Railway Postgres. Остальные параметры перечислены в `.env.example`. Секреты не добавлять в Git.

Публичный сайт и API запускаются командой `npm start`. `GET /api/health` проверяет соединение с PostgreSQL. `GET /api/config` возвращает включенные функции. Локально без базы сайт продолжает обслуживаться, API сообщает о недоступной базе.

Три флага по умолчанию выключены: `ACCOUNTS_ENABLED`, `ORDERS_ENABLED`, `SUPPORT_ENABLED`. Приём заказа также требует `PAYMENTS_ENABLED`. Не включать их до подключения почты, платёжного сценария и проверки конечного пути. Интерфейс оформления пока остаётся демонстрационным.

## Что ещё требуется для реального запуска

1. Подключить сервис транзакционных писем и домен отправителя: подтверждение email, восстановление пароля, письма о заказе и обращении
2. Подключить Stripe после подготовки компании; сервер должен подтверждать платёж по webhook до статуса «оплачен»
3. Проверить границу зоны доставки и адреса в городе Валенсия; сейчас почтовый индекс проверяется грубо, адрес помечается как непроверенный, интервал - как незабронированный
4. Связать новые серверные аккаунты и историю заказов с существующим интерфейсом кабинета и перенести локальные данные только после подтверждения владения аккаунтом
5. Включить отправку форм поддержки и возврата после настройки канала ответа; загрузка фото требует R2
6. Принять решение по подарочным наборам с динамическим составом: сервер пока не считает их как обычные SKU
7. Настроить резервное копирование, аудит и наблюдение за ошибками перед приёмом реальных заказов

## R2

В `assets/` сейчас примерно 1150 файлов общим размером 874 МиБ. Скрипт без флагов только считает их. Для загрузки нужны `R2_ACCOUNT_ID`, `R2_BUCKET`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`. После загрузки запустить `npm run assets:r2 -- --verify` и проверить публичный адрес нескольких файлов. Только затем задать `R2_PUBLIC_BASE_URL` и `R2_MEDIA_REDIRECT_ENABLED=true` на Railway. Локальные файлы можно удалять из репозитория только после полной проверки.
