# Серверная часть CatManDog

## Подготовлено

- Один Node.js сервис обслуживает существующий сайт и API на том же домене
- PostgreSQL подключается через `DATABASE_URL`; при запуске создаются таблицы и импортируются карточки и варианты из каталога
- Исходные розничные цены сохраняются отдельно от цены продажи и закупочной цены
- Все импортированные цены требуют подтверждения оператором до настоящего заказа
- API рассчитывает состав корзины и доставку сам, не доверяя цене из браузера
- Заказы, позиции, история статусов, обращения, клиенты и питомцы имеют отдельные таблицы
- У оператора есть страница `/admin` для заказов, цен, закупки, остатков и доступности
- Регистрация, подтверждение email, вход, выход и восстановление пароля подготовлены с одноразовыми ссылками, хешированием пароля и серверной сессией в HttpOnly cookie
- Настоящий кабинет загружает питомцев, контакты, планы, выбранные клиники и поездки с сервера. Изменения сохраняются в PostgreSQL; версия записи защищает от незаметной перезаписи с другого устройства
- Настоящий кабинет не принимает из браузера заказы, промокоды и бонусы; локальный пример Лео остаётся отдельным демонстрационным режимом
- Фото скопированы в отдельный bucket R2 `catmandog-media`; сайт пока использует прежние локальные файлы до подключения публичного домена

## Включение

`DATABASE_URL` уже должен быть reference variable от Railway Postgres. Остальные параметры перечислены в `.env.example`. Секреты не добавлять в Git.

Публичный сайт и API запускаются командой `npm start`. `GET /api/health` проверяет соединение с PostgreSQL. `GET /api/config` возвращает включенные функции. Локально без базы сайт продолжает обслуживаться, API сообщает о недоступной базе.

Три флага по умолчанию выключены: `ACCOUNTS_ENABLED`, `ORDERS_ENABLED`, `SUPPORT_ENABLED`. Приём заказа также требует `PAYMENTS_ENABLED`. Для настоящих аккаунтов нужны `RESEND_API_KEY`, `RESEND_FROM` и публичный HTTPS-адрес `PUBLIC_BASE_URL`. После подтверждения домена отправителя и проверки письма можно включить `ACCOUNTS_ENABLED=true`. Оплата и оформление пока остаются демонстрационными.

## Что ещё требуется для реального запуска

1. Подключить и проверить домен отправителя в Resend, добавить ключ и адрес отправителя в Railway, проверить регистрацию, подтверждение и сброс пароля на настоящем сайте. Письма о заказе и обращении ещё не реализованы
2. Подключить Stripe после подготовки компании; сервер должен подтверждать платёж по webhook до статуса «оплачен»
3. Проверить границу зоны доставки и адреса в городе Валенсия; сейчас почтовый индекс проверяется грубо, адрес помечается как непроверенный, интервал - как незабронированный
4. После запуска реальных заказов связать их историю с кабинетом. В текущей таблице заказов нет привязки к питомцу. Если понадобится перенос локального прототипа, запрашивать его отдельно после подтверждения владения аккаунтом
5. Включить отправку форм поддержки и возврата после настройки канала ответа; загрузка фото требует R2
6. Принять решение по подарочным наборам с динамическим составом: сервер пока не считает их как обычные SKU
7. Настроить резервное копирование, аудит и наблюдение за ошибками перед приёмом реальных заказов

## R2

В `assets/` 1150 файлов общим размером около 874 МиБ. 19 октября 2026 года они загружены в bucket `catmandog-media` в Western Europe. Повторная проверка `npm run assets:r2 -- --verify` нашла 1150 совпадений по размеру и SHA-256, без пропусков. Токен миграции ограничен этим bucket и действует одну неделю; временные локальные файлы с ключами удалены.

19 октября `catmandog.es` добавлен в бесплатную зону Cloudflare. В неё перенесены DMARC и `_domainconnect`; парковочные A-записи GoDaddy заменены на CNAME Railway, добавлена TXT-запись для проверки домена. В Railway создан собственный домен `catmandog.es` на порту 8080. В Cloudflare опубликованы правила перенаправления `www` на основной домен для HTTP и HTTPS с сохранением пути и параметров. У GoDaddy установлены NS `dion.ns.cloudflare.com` и `lauryn.ns.cloudflare.com`; регистратор подтвердил запрос, но обновление делегации и проверка Railway ещё ожидаются.

После активации зоны подключить `img.catmandog.es` к bucket, проверить несколько файлов через HTTPS и только потом задать `R2_PUBLIC_BASE_URL` и `R2_MEDIA_REDIRECT_ENABLED=true` на Railway. Локальные файлы можно удалять из репозитория после проверки нового публичного адреса и сайта.
