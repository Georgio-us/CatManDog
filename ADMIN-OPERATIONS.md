# Операционная панель CatManDog

Адрес: `/admin`

## Доступ

- Владелец входит через Google. Его Google `sub` записывается в `staff_accounts`; публичная регистрация сотрудников отсутствует
- Для первого назначения владельца требуется одновременно действующий `ADMIN_TOKEN` из Railway и подтверждённый Google-вход. После назначения этот ключ не открывает административные API
- Административная сессия хранится в отдельной таблице, действует 8 часов и передаётся в `HttpOnly`, `SameSite=Strict` cookie с путём `/api/admin`
- Сервер проверяет роль на каждом административном запросе. Поддержка видит только обращения
- После успешного первого входа `ADMIN_TOKEN` следует удалить из Railway. Повторное назначение владельца через форму заблокировано

## Первый рабочий срез

- «Сегодня» показывает задачи по каталогу, заказы в работе, новые обращения и продажи только по оплаченным заказам за 30 дней
- «Ревизия SKU» показывает все варианты, подтверждение розничной цены, закупочную цену, основного поставщика, доступность и пропуски в данных
- Поиск и фильтры помогают собрать список SKU без цены, закупки или поставщика
- Для SKU можно сохранить заметку и приоритет. Эти поля не перезаписываются при импорте статического каталога
- «Поставщики» хранит контакты, условия и срок поставки. К SKU можно добавить несколько предложений и выбрать основного поставщика; цена предложения отмечается как с IVA или без IVA
- Изменения основных условий SKU записываются в `admin_audit_events`

## Границы текущего этапа

- Приоритет SKU сейчас служит для ревизии. Порядок товаров на витрине он ещё не меняет
- Предложение поставщика и поле закупочной цены SKU хранятся раздельно. Автоматический выбор поставщика и расчёт полной себестоимости ещё не подключены
- Импорт из `data.js` продолжает обновлять название, категорию, изображение и исходную цену. Редактировать эти поля через панель до переноса мастер-каталога в базу нельзя
- Заказы и остатки пока имеют существующий порядок работы; полноценный журнал движений, резервирование и закупочные заказы относятся к следующему этапу
- До подключения оплаты аналитика не должна считать созданные заказы оплаченной выручкой
