# Отдельная тестовая среда оформления

Тестовая среда использует тот же код витрины и оформления, но отдельный URL, отдельную пустую базу PostgreSQL и Stripe Test Mode. На странице видна плашка «Тестовая среда». Заказы и платежи из неё не попадают в рабочую базу и отчёт о реальной выручке. Письма, Telegram и интеграции доставки в тестовом режиме выключены.

## Подключение

1. Создать в Railway отдельный сервис из этого репозитория и **отдельный PostgreSQL**. Не связывать его с рабочим Postgres.
2. Скопировать переменные из `.env.staging.example` в настройки тестового сервиса. `STAGING_DATABASE_URL` должен ссылаться только на новый PostgreSQL; `DATABASE_URL` в тестовом сервисе не задавать.
3. Указать публичный HTTPS-адрес тестового сервиса в `PUBLIC_BASE_URL`. Адрес `catmandog.es` и `www.catmandog.es` запрещены.
4. Задать отдельные логин и пароль для HTTP Basic Auth. Пароль должен содержать не меньше 16 символов. Доступ к сайту, API и админке требует этот вход; Stripe webhook пропускается через отдельную проверку подписи Stripe.
5. В Stripe **Test Mode** создать секретный ключ и webhook endpoint `https://<тестовый-домен>/api/stripe/webhook`. Подписать события `checkout.session.completed`, `checkout.session.async_payment_succeeded`, `checkout.session.async_payment_failed`, `checkout.session.expired`. Секрет webhook и ключ Stripe добавить только в переменные тестового сервиса.
6. Открыть `/api/health` после входа: база должна быть `connected`. Затем открыть `/api/config`: `testEnvironment`, `ordersEnabled` и `paymentsEnabled` должны быть `true`.

Запуск останавливается с ошибкой, если в тестовый сервис попал живой ключ Stripe, рабочий `DATABASE_URL`, боевой домен, ключи Resend или Telegram, либо включены аккаунты, поддержка, перевозчик или резервное копирование. Пустая тестовая база помечается как `staging`; существующую непомеченную базу тестовый режим не принимает.

## Контрольный проход

1. Войти на тестовый сайт и убедиться, что видна плашка «Тестовая среда».
2. Добавить два товара, пройти корзину и местную доставку, указав тестовые контакты и проверяемый адрес.
3. Проверить сумму на экране «Всё верно?», открыть Stripe Checkout и оплатить тестовой картой из документации Stripe. Реальные деньги не списываются.
4. После возврата проверить экран подтверждения и статус `paid` через `/api/checkout/status?session_id=...`. После подписанного webhook оплата появляется в отдельной тестовой базе.
5. Повторить на мобильной и десктопной ширине. Для срочной ветки отправить тестовую заявку: она сохраняется только в тестовой базе, без письма и Telegram.

Ссылку оплаты и тестовые секреты нельзя использовать на рабочем сайте. Тестовая среда не оформляет реальную доставку.
